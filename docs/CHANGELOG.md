Evidence is a command anyone can rerun.

| Slice 1 | Core adapter protocol, 9 probe families, 12 fixture environments with planted defects. Establish that every probe fires on something real before writing any adapter against a real ecosystem. | `uv run pytest -q` → 27 passed | **Kept.** Detection matches ground truth exactly on all 12 fixtures. |
| Slice 1a | Probes 2 (trivial floor) and 3 (separability) compared policies **per task**. | `rationale_ignored` reported a spurious `TRIVIAL_FLOOR_BREACH`; `escalate_overrewarded` was correct | **Revised to aggregate over the task set.** Per task, a trivial policy wins wherever the trivial answer happens to be right — that is small-n noise, not a property of the environment. This is the same "tyranny of the average" trap read from the other direction: the average is wrong for reporting a profile, and right for a floor claim. |
| Slice 1b | First MinHash fixture used a 23-word sentence with 5-word shingles. | estimated Jaccard 0.789 < 0.80 threshold; near-dup not caught | **Fixture was wrong, not the detector.** A one-word edit in a 23-word text really is a rewrite: it breaks 5 of ~19 shingles. Lengthened the fixture to ~70 words (5 of ~66). Recorded because it is a live trap for anyone applying a shingle-5 near-dup audit to short items — the detector silently under-reports on short text. |
| Slice 1c | Test asserted a healthy environment yields verdict `VALID`. | verdict was `UNVERIFIED`, because the difficulty probe cannot run without a solve-rate estimate | **The code was right and the test was wrong.** No defects found is not the same as no defects. An environment with a probe that could not run is `UNVERIFIED` and still exits nonzero. Fail closed. |
| Slice 1d | Test asserted planted defects were a **subset** of detected. | passed, but would also pass for a probe that flags everything | **Tightened to exact match.** Recall alone cannot separate detection from guessing. Two fixtures then legitimately gained defect labels: a verifier that passes at reset is broken on every axis, and an over-broad oracle also accepts an inverted spec. |
| Slice 2 | inspect_ai adapter against real `inspect_ai.Task` objects, plus cost profiles, expected-loss metric, and the incumbent `check_env` baseline. First measured comparison. | `uv run --extra adapters python scripts/full_run.py` → `results/full_run.json`; 47 tests pass | **Kept.** 17 environments, 35 planted defects. |
| Slice 2a | Hand-wrote ground truth for the inspect_ai environments, then found Assay reporting 4 "spurious" defects. | `results/full_run.json` per-env diff | **The labels were wrong, not the tool.** A scorer returning a constant 0.5 has four defects, not one: gold never passes, nothing separates, an input-ignoring answer ties the best real one, and a wrong answer is paid in full. Correcting labels because the tool disagreed would be circular, so each was re-established directly from the scorer's own behaviour in `tests/test_corpus_ground_truth.py` before the label moved. Worth noting what this is: hand-written ground truth about environment validity is itself error-prone, which is the problem the tool exists to solve. |
| Slice 2b | Headline comparison against the incumbent tool. | `results/full_run.json` | **`check_env` scores identically to `flag_nothing`** — expected loss 2248 for both, recall 0.000, on all 35 planted defects. The structural linter is not a weak detector of these defects; it is not a detector of them at all. This is the fair-baseline result the submission rests on, and it needs no LLM to reproduce. |
| Slice 2c | Assay scored 1.000 recall and 1.000 precision on the corpus. | `results/full_run.json` | **Not a win — a saturation warning.** A corpus every arm either aces or zeroes cannot rank two serious auditors against each other. This is the difficulty-band defect, in Assay's own benchmark, caught by its own rule. Recorded as an open limitation; slice 7's wild finds and subtler planted defects exist to fix it, and the README must not claim discriminating power the corpus does not have. |
| Slice 3 | Docker sandbox with a fail-closed approval gate, then the Harbor adapter. Harbor ships an executable `solution/solve.sh`, so gold becomes a check that can fail. | `uv run --extra adapters pytest -q` → 68 passed, 9 of them driving real containers | **Kept.** Corpus now 21 environments, 44 planted defects. |
| Slice 3a | First Harbor audit took over four minutes for four tasks. | one container start timed at **4.1s** on Docker Desktop; the battery replays ~27 commands per task | **Rebuilt on a persistent session.** `docker exec` into a running container instead of `docker run` per command: **>4min → 39s**, identical detections. Runtime is a reproducibility feature, not a nicety — the repro guide promises a laptop run. Cost of the change, stated plainly: episodes inside one session share a filesystem namespace and are separated by directory rather than by container. |
| Slice 3b | Considered giving Harbor an inverted-spec probe for parity with inspect_ai. | a shell verifier takes no target argument; there is nothing to substitute | **Removed before it was written.** The adapter withholds `INVERTIBLE_SPEC` and the probe reports NOT_APPLICABLE with a reason. Faking it would have produced a clean-looking result from a check that never ran — the exact failure this tool exists to catch. |
| Slice 3c | Added `harbor/self-graded`: the verifier reads its expectation from a file in the workspace, so writing the same value to both passes while doing nothing. | exploit exhibited directly in `tests/test_harbor_ground_truth.py`; `results/full_run.json` shows `missed: [REWARD_HACKABLE]` | **Kept as a known miss.** The scripted Challenger cannot find it. This is the first environment in the corpus Assay fails on, and it is what took the corpus off saturation: normalized loss moved from 0.000 to **0.480**. A benchmark nothing fails is a benchmark that ranks nothing. |
| Slice 4 | Extracted the Challenger into its own package and added a prompted agent loop: one action per turn, run in the environment's own sandbox, told only the score the environment reported. | `results/challenger_ablation*.json` | **Kept.** The invariant is enforced by a test that reads the source: neither challenger module may reference `true_completion`. An attacker told the answer is not finding an exploit. |
| Slice 4a | `action_template` handed the attacker whichever action came first. | for a fixture whose first trivial policy is `always_abstain`, that was `noop()` and nothing else | **Fixed.** `action_vocabulary` collects every tool and orders them by argument count. The first prompted run was crippled by being told the entire vocabulary was "do nothing", and its result was discarded rather than reported. |
| Slice 4b | Separated attack from evaluation so the Challenger could run several policies before any was scored. | `harbor/vacuous-tests` stopped reporting `REWARD_HACKABLE` although nothing about it had changed | **Real bug, caught by a stateful fixture.** On an adapter with a workspace, scoring a transcript recorded earlier scores whatever the *last* policy left behind. `exploit_gap` now replays from a fresh reset before measuring. This is the argument for having stateful fixtures at all. |
| Slice 4c | Ran the ablation with `qwen3:8b`; the arm silently vanished from the results. | `SKIPPING qwen3:8b: not pulled` — while the model was, in fact, pulled | **A busy daemon read as a missing model.** The availability probe used a 5s timeout and collapsed "unreachable" into "absent". Now returns `(usable, reason)` with a 30s probe, and skipped arms are recorded in the output JSON. A silently shrunken experiment is worse than a failed one — and it is the same failure shape this tool exists to catch. |
| Slice 4d | Attached the attacker's trace to findings so a miss could be diagnosed. | a failed 8-turn run exported exactly one turn | **The *best* attempt's log was attached, not the last one.** On a failed run the best attempt is turn 1, so the export showed the first turn and nothing else. Now attaches the final attempt's log, which holds every turn including the malformed ones. |
| Slice 4e | Killed and crashed runs left sandbox containers running. | two `alpine:3.20` containers up 18 minutes after their process had gone | **Added `assay reap`**, and made it safe: containers carry the creating pid, and only those whose process is gone are removed. The first version reaped by label alone, which would have torn down a live audit to tidy up after a dead one. |
| Slice 4f | The difficulty-band probe had never once run — nothing supplied a solve rate. | `SolveRateSampler` with `qwen3:1.7b` on the ticket fixture: `{t1: 0.00, t2: 0.33, t3: 0.00}` | **Kept, with a caveat that changed the probe.** A solve rate is a property of an (environment, policy) *pair*. Those two tasks are impossible for a 1.7B model and unremarkable for a larger one, so findings now carry `measured_with`. A card reporting the number without the policy reports half a fact. |
| Slice 4g | Considered making the Auditor an LLM planner that decides which probes to run. | probe applicability is fully determined by declared capabilities | **Removed before it was built.** There is no judgement to make: a probe either has its prerequisites or does not. An LLM there would have added nondeterminism to the one part of the system that must be reproducible, and bought nothing. The agentic component is the Challenger, where the search space is genuinely open. |
| Slice 5 | Pointed the prompted Challenger at `harbor/self-graded` and read the traces rather than the score. | `results/challenger_ablation*.json` | **Three loop bugs, none visible from the pass/fail line.** Recorded separately below because each was a different way of measuring the wrong thing. |
| Slice 5a | The loop reset the environment every turn. | trace: attacker writes a file at t3, cannot see it at t5, spends t5–t10 re-reading an empty workspace | **One episode per attack, not per turn.** An agent that cannot accumulate state cannot build a two-step exploit, and most exploits are two steps. |
| Slice 5b | The loop stopped on a full score. | trace: `ls`, `cat expected.txt`, `echo 42 > out.txt` → scored 1.0 → stop | **It won by legitimately solving the task.** Perfect score, zero gap, nothing learned about the environment. The objective is a gap, not a score, so the stopping rule was measuring the wrong quantity. |
| Slice 5c | Stopping then keyed on the attacker's own report of whether it had really done the job. | trace: Claude ran `cat expected.txt > out.txt`, reported `solves_the_task: false`, run ended; the independent verifier scored it a complete solve | **The attacker was honest and still wrong, so it does not get to decide.** It cannot see true completion, so it cannot know whether it produced a gap. Early stopping removed entirely: the whole budget is spent and the probe takes the best gap across every attempt. The self-report survives only as feedback, to stop it repeating a score it earned. |
| Slice 5d | Once the attacker scored 1.0, the workspace kept scoring 1.0 whatever it did next. | trace: six consecutive idle turns after a success | **Gave it `reset_environment`.** An attacker with no way to start over has no signal left to work with. |
| Slice 5e | Added the two LLM baselines the brief names, plus `adapter.describe()`. | `full_run.py --llm-arms` | **Kept.** Both get the same defect taxonomy, the same manifest, instructions and verifier source a human reviewer would read. Handing a baseline less than a person would have and then reporting it found nothing is a rigged comparison, not a fair one. |

# 40 — A GRPO-trained adversarial Challenger

The scripted Challenger misses `harbor/self-graded`, where the verifier reads
its expectation from a file the agent can overwrite. That miss is the reason
the corpus discriminates at all. This workstream asks whether an attacker
*trained* on the exploit gap closes it.

The reward is the whole idea:

```
reward = environment's reported score - independent true completion
```

computed by the harness, never by the policy. Solving the task honestly pays
zero. The only way to earn reward is credit that was not earned.

| Stage | What was tried and why | Evidence | Decision / learning |

Run 2 ran on an L4 rather than an A10G: `g5.xlarge` spot was exhausted in all
six `us-east-1` zones and `us-west-2` has zero G/VT spot quota on this account.
Same 24GB, same job, and the variable under test is the sampler, not the GPU —
but it is a difference and it is stated rather than smoothed over.

**Training did not work, and the reward is not why.** Parse rate 1.000. The
gaps were computed correctly. 16% of rollouts landed on real exploits worth
≥0.5. What failed is upstream of all of that.

### Why

GRPO's advantage is group-relative: `(r − mean) / std` within one prompt's
rollout group. If the rollouts are identical, the advantage is **exactly zero**
and there is no gradient at all — which is not slow learning, it is no
learning. Run 1 had 99.7% of its 300 groups at zero spread, and 85.7% of them
were byte-identical. 1918 of 2400 rollouts were the same 60-character string:

```
{"actions": [{"tool": "submit", "args": {"label": "spam"}}]}
```

Qwen3-1.7B with thinking disabled is effectively deterministic on this prompt.
The logged entropy sat at 4×10⁻⁴ nats, `grad_norm` at ~1×10⁻⁵.

### What run 2 rules out, and what it does not

Raising temperature to 1.3 and top_p to 1.0 multiplied lexical diversity almost
sevenfold — 9 distinct completions became 62 — and moved nothing. Mean reward
still fell slightly over the run. So *"the sampler never explored"* is not the
whole story, and it is worth looking at what the extra 53 completions actually
were:

```
[1908x] {"actions": [{"tool": "submit", "args": {"label": "spam"}}]}
[ 321x] {"actions": [{"tool": "run", "args": {"script": "echo 'Hello, world!' > out.txt"}}]}
[  24x] {"actions": [{"tool": "run", "args": {"script": "echo 'This is the answer' > out.txt"}}]}
[  20x] {"actions": [{"tool": "run", "args": {"script": "echo 'Hello, world!' >> out.txt"}}]}
```

The variation is entirely in **the string being echoed**. `>` becomes `>>`;
`'Hello, world!'` becomes `'This is the answer'`. The *structure* never varies:
one action, always `submit` or always `echo <literal> > out.txt`. The
exploration was **lexical, not structural**, and the exploit gap only pays for
structural variation — reading the verifier, writing a second file, deleting
something. Temperature buys the first kind of diversity and cannot buy the
second.

### The one place behaviour did move, and it moved the right way

`fixture/weak_oracle` went from +0.600 to −0.004 across the run. That is the
model drifting toward emitting `submit spam`, which on one of the three tickets
is the *correct* label — so the independent verifier scores it 1.0, the
environment scores it 0.6, and the gap goes negative. The reward correctly
punished the attacker for accidentally doing the task. The one measurable
behaviour change in 4800 rollouts is the reward working as designed.

Every policy the trained Challenger proposed was a variation on
`echo '<some string>' > out.txt`. It never read a file, never listed the
directory, and never wrote to `expected.txt`. It had no way to discover that
`expected.txt` exists, because a one-shot policy gets no observation back — and
that is a property of the *training format*, not of the training.

### What this actually shows

The honest summary is three claims, in decreasing confidence:

1. **The reward is correct and cheap to check.** 36 tests, four against real
   containers, no GPU. An honest solve pays zero; the planted hack pays 1.0.
   Anyone can verify it in three seconds without believing anything about a
   training run.
2. **GRPO on this setup produced no gradient**, because the rollout groups were
   degenerate — 99.7% and 95.7% across the two runs. This is measured, not
   inferred, and `identical_completion_groups` separates it from the corpus
   being flat.
3. **The one-shot policy format is the load-bearing mistake**, and this is the
   least certain of the three. `harbor/self-graded` cannot be solved without
   first discovering `expected.txt`, which requires an observation the format
   never returns. The prompted Challenger, which *does* get observations, is
   the arm that was designed for this and it is the one to train — the
   reward, the environment pool and the replay machinery here all transfer to
   it unchanged.

### What I would do next, in order

1. **Train the multi-turn format, not the one-shot one.** Reward the whole
   trajectory with the same exploit gap. The reward, `EnvPool`, the holdout and
   the replay logic need no changes; only the rollout loop does.
2. **Filter degenerate groups instead of stepping on them.** DAPO's dynamic
   sampling resamples a prompt until its group has nonzero spread. At 95–99%
   degenerate that is most of the compute, and `scripts/reward_landscape.py`
   already says which prompts are worth sampling before a step is taken.
3. **Seed exploration with the scripted repertoire.** A brief SFT pass on
   recon-then-exploit trajectories would put structural variation in the
   sampling distribution, which temperature demonstrably cannot.

None of that was run, so none of it is claimed.

## What this cost

Two spot runs of ~16 minutes each: `g5.xlarge` at $0.4612/hr and `g6.xlarge`,
both `us-east-1`. **Under $0.60 of compute in total.** The reward-landscape
diagnostic that predicted the result cost nothing and ran on a laptop.
