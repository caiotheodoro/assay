| Slice 34 | The test suite did not terminate cleanly, and leaked containers indefinitely. An external reviewer's run finished its last test and **never printed a summary line**. | `src/assay/sandbox.py:260`, `docker ps --filter label=assay-session` | **Diagnosed and fixed.** There was no `tests/conftest.py`, no `atexit` and no non-daemon thread, so the hang could only be a fixture finaliser — and it was `SandboxSession.stop()`: `docker rm -f` under `capture_output=True` with a **60-second timeout and `TimeoutExpired` uncaught**. On a slow daemon that is a full minute of total silence followed by an exception raised out of teardown. Teardown that can hang is worse than teardown that can fail, because the failure at least says something. |
| Slice 34a | How far the leak had gone. | live `docker ps` on the development machine | **Fourteen orphaned containers, every creating pid dead, the oldest running for thirty-three hours.** One cluster of four shared a single dead pid — the signature of `EnvPool.close()`, which had no per-adapter guard, so the first exception aborted the loop and stranded every remaining container. `assay reap` existed, worked, and was wired into **nothing**. All fourteen removed. |
| Slice 34b | The fix, and why `container_id` is cleared first. | `sandbox.py` `stop()` | 60 s → **15 s** (`docker rm -f` is SIGKILL; there is no grace period to wait out, so if it has not returned the daemon is wedged and waiting longer converts a leaked container into a hung run), `SubprocessError` caught, and `container_id` cleared **before** the call rather than after. That ordering is the point: if removal fails the container survives still carrying its `assay-session` and `assay-pid` labels, so `reap` can find it. **A leak that is labelled is recoverable; a leak the object still believes it owns is not.** `EnvPool.close()` now guards per adapter, and `HarborAdapter.close()` reclaims its tmpdirs in a `finally` so the disk goes back whatever happens to the container. |
| Slice 34c | Making the next leak loud instead of silent. | `tests/conftest.py` (new) | A session fixture that records the containers present before the run and, after it, removes and **warns** about any orphan the run itself created. Reap-then-warn rather than reap-then-fail: a leak should be visible on the first run that causes it, but turning a green suite red over a container that has already been cleaned would train people to ignore the signal. Pre-existing orphans are reported separately and explicitly **not** counted against the run, because deleting a container a live audit still owns would be worse than leaking one. |
| Slice 34d | A published claim that was false. | `docs/REPRODUCTION.md` | The guide states *"after `scripts/full_run.py` exits, zero containers carry that run's `assay-pid` label"*. True of `full_run.py`; **false of the suite**, and contradicted by `docker ps` for thirty-three hours. Corrected to say what is actually measured, and now enforced by the fixture rather than asserted. |
| Slice 34e | One latent unbounded wait, fixed while here. | `src/assay/sweep.py` | `proc.communicate(timeout=timeout if timeout > 0 else None)` — `None` means wait forever. Nothing passes 0 today so it never fired, but "no test reaches it" is not a bound. Now falls back to a finite `HARD_TIMEOUT`, generous enough that a slow dataset download is not mistaken for a hang. |
