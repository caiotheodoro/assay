| Slice 27 | Fixed the false positive Slice 26e found: Assay reporting a defect about an environment that had not misbehaved. | `src/assay/adapters/harbor.py`, `src/assay/probes/determinism.py`, `src/assay/types.py` | **The harness giving up was being read as evidence about the environment.** `SandboxSession.exec` returns `SandboxResult(124, ..., timed_out=True)` when a `docker exec` hits the wall clock, and `HarborAdapter.step` **discarded `timed_out`** — so a timed-out repeat surfaced as exit code 124 where a healthy one had 0. The determinism probe fingerprints `(ok, data, code)` across three repeats, saw two distinct fingerprints, and reported `NONDETERMINISM`. That is exactly the failure this project audits environments for, happening inside a probe: an inconclusive observation promoted to a finding. |
| Slice 27a | The fix, in two halves. | `SANDBOX_TIMEOUT` in `types.py` | Harbor now surfaces the timeout with its own observation code and carries `timed_out` in the data, so a caller can tell *"the harness gave up"* from *"the environment answered differently"*. The determinism probe counts timed-out repeats and **refuses to compare them** — a repeat nobody finished is not a repeat that came back different. The count and the reason go into the card either way, because silence would be the same mistake in the other direction. |

PASS would be a claim it did not earn, and "a check that could not run reported as a check that passed" is the defect class this whole tool exists to find. `na()` previously dropped its detail, so a probe that had done real work and then failed to conclude left only the word NOT_APPLICABLE on the card; it now carries what was attempted, on which tasks, and how far it got. |
