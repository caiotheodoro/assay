| Slice 36 | **A confirmed HTML injection on the public Space.** | `space/app.py` | A spec whose `task_id` is `<img src=x onerror="alert(1)">` rendered **verbatim and executed**. Every string a submission controls — task ids, the text of a `SpecError` quoting the offending value, skip reasons, evidence keys, the traceback — was interpolated raw into HTML. `card/render.py` has escaped via `html.escape` since it was written; this file never did, **and this file is the one with an audience**. On a Space whose entire premise is "paste an environment you did not write", a shared spec is a delivery vector — in a project that added `safe_regex` and size caps for exactly this threat model. |
| Slice 36a | Why it survived review. | `tests/test_space_app.py` (new) | **The Space had no tests at all.** Not thin tests — zero. Nothing imported `app.py`, so nothing compared it to the renderer that does escape. Seven tests now cover it, and the two injection tests were run against the pre-fix file first: both fail there, both pass after. Escaping and truncation are applied together in one `_e()` helper, because both bound what a submission can do to the page — without the cap a 20,000-character task id is a denial-of-service on the reader. |
| Slice 36b | **A publication gate that passed a sentence asserting the opposite of what it checked.** | `scripts/publish_hf.py` | The Space card read *"Neither this Space nor the tool behind it is **not production-validated**"* — a double negative claiming the tool **is** validated, on the page whose one job is to say it is not. The gate greps for the substring `"not production-validated"`, found it inside the negation, and passed. This is the vacuous-check shape Assay flags in other people's environments — `always_pass`, a verifier that cannot fail — shipped in our own publisher, which is worse than an ordinary bug. Fixed, and a second gate now fails on the negated form specifically; verified by running it against the original sentence. |
| Slice 36c | **`--only space --push` ran zero gates and uploaded.** | `scripts/publish_hf.py` | `gates = run_gates(...) if payload is not None else []`, and only `stage_dataset()` sets `payload`. The bypass was invisible rather than loud: the gate table printed empty, `failed` was empty, and the run looked like a clean pass on its way to publishing. Gates that do not need the dataset now run regardless of which artifacts were staged, and **an empty gate list is now itself a failure** — no gates ran is never a pass. `--only space` went from **0 gates to 9**. |
| Slice 36d | The one Space-specific gate was a substring search. | `_space_behaviour_gates()` | `"NOT_APPLICABLE" in app` — satisfied by a file that only mentions the constant in a comment. It now imports the **staged** copy (the one about to be uploaded, not the one in the repo), renders a thin spec and asserts the skip table appears, then renders a hostile spec and asserts the payload came back escaped. A gate that can only pass if the behaviour it names actually happens. |
| Slice 36e | No submission could ever reach `VALID` here, and nothing said so. | `_ceiling()` in `space/app.py` | `VALID` requires every probe to have run; `difficulty_band` needs a rollout sampler a Space without Docker cannot provide. So a user whose eval is genuinely fine saw purple `UNVERIFIED` with no explanation and reasonably concluded the tool was broken. The banner now says the ceiling is a limit of the Space rather than a reservation about their environment — **only when the sampler is the sole gap**, and never beside a finding, where reassurance would be the worst of both. |
| Slice 36f | Two deployment details that would have failed on first boot. | front matter, `space/requirements.txt` | `python_version: "3.11"` — `assay.adapters.harbor` imports `tomllib` at module level and the Spaces gradio image defaults to 3.10. And the page now opens on the substring-verifier example rather than an empty box: that example *is* the argument for the tool — one constant string credited for both labels, so a policy ignoring the input scores 100% — and an empty box asks a visitor to supply the argument before seeing the tool make it. |
