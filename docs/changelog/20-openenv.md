| Stage | What was tried and why | Evidence | Decision / learning |
|---|---|---|---|
| Slice 6 | OpenEnv adapter (`huggingface/OpenEnv`), against `echo_env` and `textarena_env`/Wordle. OpenEnv is the RL environment standard the ecosystem is converging on, so whether Assay can audit it at all is the question worth answering. | `uv run --extra adapters --extra openenv pytest -q` → 145 passed (116 pre-existing, unchanged) | **Kept, and the headline result is a negative one.** Corpus now 23 environments. |
| Slice 6a | **OpenEnv has no separable verifier, so eight of the nine probe families cannot run.** `rfcs/002-env-spec.md` gives an environment `reset(seed, episode_id)`, `step(action)` and a `state` property, and reward is computed *inside* `step` and returned as a field on the `Observation`. There is no `verify`, no scorer object and no target argument anywhere on the client contract. | `results/openenv-audit.md`: **11 of 12 probes NOT_APPLICABLE on both environments**, each naming `SEPARABLE_VERIFIER` | **Reported as the finding, not worked around.** The three probes that die are the three that matter most: inverted-spec (`step` takes an action, never a target — there is nothing to invert, so the CRITICAL "can this eval fail at all" check has no surface), gold/known-wrong (re-scoring a *recorded* transcript means re-running, which measures the environment's current state rather than the transcript), and reward-hackability (the Challenger maximises a gap between the reported score and an independent reading of completion; with only one of those obtainable there is no gap). A standard that cannot express a verifier an auditor can call on its own terms is a standard whose environments nobody can QA. |
| Slice 6b | Considered extracting reward by importing each environment's server-side internals — read `env._ta_env.state.game_state["secret_word"]`, synthesise a gold trajectory, declare `GOLD_TRAJECTORY` and `SEPARABLE_VERIFIER`. | prior estimate 16–26h of bespoke work per environment, breaking on every version bump | **Refused before it was written.** The cost was not the deciding argument; the result would have been. It would have made four dead probes appear to run while measuring something no training run can see. Manufacturing clean-looking results from checks that never really happened is the exact failure this tool exists to catch, and doing it inside the tool would be worse than not having the tool. The adapter audits the client contract, because the client contract is what a training run consumes. |
| Slice 6c | `verify()`: raise `NotSupported`, or return the last step reward while the manifest honestly withholds the capability? | `tests/test_openenv_adapter.py::test_verify_refuses_an_inverted_spec_rather_than_ignoring_it` | **Raises.** Returning the reward would satisfy the signature while breaking both promises it makes. `spec` would have to be silently ignored, so a probe passing an inverted spec would get the *un*-inverted score back and believe it. And `Score.passed` would have to be invented, because OpenEnv reports a bare float with no declared scale and no declared success threshold — picking a cutoff would put the auditor's opinion inside a number the card attributes to the environment. Raising also puts the reason verbatim into the card. The reward stays reachable as `episode_reward()`, under a name that does not claim to be a verifier. |
| Slice 6d | **The determinism probe required a separable verifier, so on OpenEnv it reported NOT_APPLICABLE and found nothing.** "Same seed, same episode" is answerable from the observations an environment hands back; demanding a callable scorer silenced the probe on exactly the ecosystems most likely to fail it. | `git show fab6b08`; 116 pre-existing tests unchanged and green | **The over-constraint was the bug.** Requirement dropped to `SEEDED_RESET` alone; the scorer's verdict is still folded in when one exists, so every existing adapter takes the identical code path. This is what made the next row possible. |
| Slice 6e | **`textarena_env` accepts `seed` on `reset()` and never passes it to the game underneath.** Same seed, a different secret Wordle word every episode. | `tests/test_openenv_ground_truth.py`: six resets at seed 1234 → six different secret words, read straight off TextArena's own `game_state`; plus a source check that `reset` calls `self._ta_env.reset(num_players=...)` with no seed | **A real defect in a shipped environment, found by the battery rather than by hand.** `openenv/textarena-wordle` → `DEFECTIVE`, exit 1, detection matching ground truth exactly. This is precisely the gap the README names in gymnasium's `env_checker`, which verifies that `reset()` *accepts* a seed and never that seeding does anything ([Gymnasium #1084](https://github.com/Farama-Foundation/Gymnasium/issues/1084)) — reproduced here in a different ecosystem, on an environment people are training against. |
| Slice 6f | **The determinism probe also could not fail on any environment without a gold trajectory.** With no gold it replayed an EMPTY action list, fingerprinted an empty episode, and passed whatever the environment did. | `tests/test_openenv_ground_truth.py::test_an_empty_replay_would_have_missed_this_entirely` runs both code paths side by side on Wordle: old path 1 distinct fingerprint → PASS, new path 2 → DEFECT | **Assay's own vacuous check, caught by Assay's own rule.** Recorded rather than quietly fixed: this is a `NOOP_PASSES` defect in the auditor, of the same shape as the ones it flags in environments. It now falls back to an input-ignoring policy, and folds in the reset observation — the seed is consumed at reset, so an environment redrawing its hidden state per episode is invisible if you only look at what happened afterwards. Every existing environment ships gold, so no existing result moved. |
| Slice 6g | Wanted a trivial-floor number from the reward `step()` does return, since that probe needs no verifier in principle. | three consecutive runs of the `describe()` table in `results/openenv-audit.md`: `repeat_one_guess` 0.1 / 0.4 / 0.2, `fixed_six_guesses` 0.0 / 0.1 / 0.1 | **Not reported as a probe result, and the reason is the interesting part.** Two blockers, and only the first was expected. Nothing on the client contract declares a pass threshold, so "does a trivial policy win" has no defined answer. And the numbers are not comparable anyway: each policy plays against a different secret word, so a floor measured across them is measuring the dice. **A trivial floor needs a fixed task to measure against, and a nondeterministic environment does not offer one** — the two defects compound rather than sitting side by side. The reward table is printed in `describe()` for a human reviewer instead, which is what the LLM baselines already receive. |
| Slice 6h | `echo_env` as the wiring-only smoke target. | `results/openenv-audit.md`: reward `[0.0, None]` — 0.0 at reset, `None` on every MCP action | **Kept, ground truth empty, and the verdict is still not `VALID`.** `MCPEnvironment` never sets a reward, so there is nothing for a validity probe to measure even in principle. The entry earns its place by proving the in-process seam works against a real shipped environment rather than a mock. `UNVERIFIED`, exit 1: an empty defect set means "nothing this battery can see", not "clean", and the card has to keep those apart. |
| Slice 6i | Docker and uvicorn/`base_url` were the documented paths to an OpenEnv environment; tried instantiating the server-side `Environment` subclass directly instead, as OpenEnv's own tests do. | `tests/test_openenv_adapter.py::test_echo_runs_in_process_without_docker_or_http`; full OpenEnv suite runs in ~4s | **In-process, no fallback needed.** A container adds a process boundary, a serialization round trip and a startup cost without adding a single observation, and a probe battery that needs Docker is a probe battery that does not get run — the same argument that cut the Harbor suite from 4min to 39s in slice 3a. |
| Slice 6j | `echo_env` and `textarena_env` are not on PyPI; only the `openenv` framework is. | `pyproject.toml` `openenv` extra, pinned to `e059726` | **Installed by direct git reference at a fixed revision.** An audit whose subject moves between runs is an audit nobody can reproduce. The corpus provider reports its own unavailability with a reason — naming the missing module, or the missing NLTK `words` corpus — rather than downloading behind the caller or letting the corpus shrink in silence. |
