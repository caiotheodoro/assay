| W2a | First question was whether a task-safety filter earns the coverage it costs. | `InspectAdapter` fabricates a `TaskState` carrying only `output.completion`; a scorer reading `state.store` gets `{}` and returns a score, silently | **The filter is a correctness requirement, not an optimisation, and it is the whole design of `sweep.py`.** For `match`/`pattern`/`includes` the fabricated state is exactly faithful. For a scorer reading a sandbox, a tool transcript, or the store it is not faithful *and does not raise* — it returns a degenerate score computed from an empty world, and every such score looks like a finding. Sweeping without the filter would emit fabricated defect reports against real published benchmarks, which is worse for this project than finding nothing. |

| W2f | Bounded dataset materialisation with `signal.alarm`. | `docvqa` took the HF cache past **18 GB** with a 240 s budget nominally in force; the sweep had to be killed by hand, and a later run reached 30 GB on `mmiu`/`mathvista` and did not survive it | **It does not work, and the fix is a process boundary.** A factory pulling a multi-gigabyte dataset sits inside `datasets`' C-level download and never reaches a bytecode boundary where the handler could run. | W2g | Ran the sweep and triaged every hit by hand. | `uv run --extra adapters --extra sweep pytest tests/test_wild_findings.py -q` → 26 passed; `results/wild_sweep.json` task `paws`, and `results/wild_sweep_triage.json` | **`paws` is a real, unplanted, CRITICAL defect in a published eval.** It scores with `includes()` — a case-insensitive *substring* test — against the targets `"Yes"` and `"No"`. Every one of `"I cannot determine the answer."`, `"I don't know"`, `"Not sure"`, `"None of the above"` is marked CORRECT whenever the target is `"No"`: each contains the substring in *cannot*, *know*, *not*, *none*. The looseness is one-sided, which is worse than symmetric — it makes the No class (4464 of 8000 items) systematically easier for any model that hedges. The strongest form is a single constant string: **`"yesno"` contains both labels and scores 8000/8000 = 100.0%.** This is the WebArena substring-match failure from the README's own table, live in a benchmark shipping today. Verified from `inspect_evals`' own `record_to_sample` and `inspect_ai`'s own `includes()`, with Assay out of the loop. |
| W2h | What Assay itself found, and what it did not. | 14 of 25 sampled `paws` items report `REWARD_HACKABLE`, `exploit_policy=trivial:always_escalate`, `exploit_gap=1.0`, verdict INVALID; `tests/test_wild_findings.py::TestWhatAssayItselfFound` | **The tool found the weaker half and hand triage found the stronger, and that split is pinned as a test so it cannot quietly close in the write-up.** The scripted Challenger's repertoire *is* the adapter's trivial policies, and none of them names both labels at once. `TRIVIAL_FLOOR_BREACH` also, correctly, did not fire: the escalate policy averages 0.56 against gold's 1.0, and the probe's rule is that a trivial policy must *tie or beat* the best real one. | W2i | Checked whether the same two-short-labels hazard was mishandled elsewhere in the swept scope. | `tests/test_wild_findings.py::TestBoolqAnchoredPattern` | **`boolq` is the contrast that makes the `paws` finding legible, and a narrower leak of its own.** Same targets, but scored `pattern(r"(Yes\|No).?\Z")`. Anchoring at the end is a real mitigation: most refusals come back NOANSWER instead of credited, and no constant string satisfies both targets. It still leaks — `.?` admits exactly one trailing character and *know* is *no* plus *w*, so `"I don't know"` is CORRECT on every No-targeted item. That is the argument for the prompted Challenger, stated as a test rather than as a hope. |
| W2j | Whether a subsampled audit of these evals is repeatable at all. | two runs of this sweep at `--seed 0` reported **18 then 17** findings on `paws`; two identical `paws()` calls return sample ids `['7531','6916','818',…]` and `['7622','1046','5001',…]` | **It was not, and the cause is not specific to the audit.** `paws`, `boolq` and **35** task modules default to `shuffle=True` with no seed, so any run using `--limit N` — the standard way to run a subset — draws different items each time and two limited runs are not comparable. `sample_indices` was deterministic; the list it indexed into was not. The sweep now passes `shuffle=False` where the factory accepts it (18 of 58 kept tasks) and records it per task in `task_args` rather than applying it silently. Two full runs are now byte-identical, down to which sample ids carry findings. Assay's determinism probe did not catch this because it checks that *scoring* is reproducible given a fixed dataset, not that *dataset construction* is — a genuine gap in the family, recorded rather than quietly patched into a probe this workstream did not scope. |
