| W2a | First question was whether a task-safety filter was worth the coverage it costs. | `InspectAdapter` fabricates a `TaskState` carrying only `output.completion`; a scorer reading `state.store` gets `{}` and returns a score, silently | **The filter is a correctness requirement, not an optimisation, and this is the whole design of `sweep.py`.** For `match`/`pattern`/`includes` the fabricated state is exactly faithful. For a scorer reading a sandbox, a tool transcript, or the store it is not faithful *and does not raise* — it returns a degenerate score computed from an empty world, and every such score looks like a finding. Sweeping without the filter would emit fabricated defect reports against real published benchmarks, which is worse for this project than finding nothing. |

| W2d | The gold anchor, per item rather than per task. | W2e | Multiple-choice tasks would all have failed the anchor: `choice()` reads `state.choices`, which the `multiple_choice` *solver* populates, and a bare `"A"` as the completion marks nothing. | `arc_easy`, `arc_challenge`, `hellaswag`, `commonsense_qa`, `gpqa_diamond` all anchor 25/25 under `protocol=multiple_choice`, 0/25 under `raw` | **Replayed the solver's own step rather than simulating it.** The completion is formatted the way `inspect_ai`'s `SINGLE_ANSWER_TEMPLATE` asks, then `inspect_ai`'s own `parse_answers` and `set_choices_based_on_generated_response` are called — the `Choices` object the scorer reads is built by the library, not by this file. `multiple_correct` is read out of the solver's closure and the task is refused if it cannot be read: a multi-answer task scored as single-answer would mark every gold wrong and look like a broken benchmark. |
| W2f | Bounded dataset materialisation with `signal.alarm`. | `docvqa` took the HF cache past **18 GB** with a 240 s budget nominally in force; the sweep had to be killed by hand | **It does not work, and the fix is a process boundary.** A factory pulling a multi-gigabyte multimodal dataset sits inside `datasets`' C-level download and never reaches a bytecode boundary where the handler could run. Each task now sweeps in its own process *group*, killed outright on expiry — `datasets` spawns workers, so killing the parent alone leaves them downloading. Isolation is worth more than the timeout: a task that segfaults costs one row instead of the sweep, and a sweep that died partway while reporting its prefix as the whole picture is the silent-gap failure this module exists to prevent. |
